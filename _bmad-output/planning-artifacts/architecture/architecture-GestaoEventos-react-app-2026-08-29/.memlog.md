- (decision) Adotar Expo universal como plataforma do novo app React do GestaoEventos, com uma base para Android, iOS e web. Binds: todos os fluxos React. Prevents: dois clients divergentes para web e mobile, ou uma migracao web que precise ser reescrita depois para mobile.

Binds: go-live, QA, roadmap de migracao. Prevents: publicar um app parcial que substitui o produto funcionando.
- (decision) Adotar paradigma Feature-Sliced Layered Client: app routes/screens compoem UI, features concentram componentes/hooks de dominio, business hooks/services orquestram regras e cache, API services fazem HTTP puro e conversao de case, stores guardam apenas sessao/contexto/preferencias globais, React Query e dono de dados remotos. Binds: todos os modulos React. Prevents: chamadas HTTP diretas nas telas, caches duplicados em Zustand, e features divergindo em forma de estado e transformacao.
- (decision) Manter o design system do GestaoEventos como fonte visual do React: brand blue #0066FF, superfícies claras, UI SaaS/admin operacional, nomenclatura agnostica e densidade controlada. ManagerPersonTrainer.React serve apenas como referencia tecnica de Expo/React, nao de paleta, tom visual ou componentes fitness. Binds: design tokens, componentes base, telas e navegacao. Prevents: importar identidade dark/lime de academia e descaracterizar o produto.
- (decision) Autenticacao/contexto no React: JWT em expo-secure-store, contexto ativo em Zustand com persistencia local, revalidacao do contexto no backend apos login/hydrate, troca de estrutura invalida React Query e limpa grupo selecionado quando fora da nova estrutura; UI apenas reflete permissao e backend permanece autoridade. Binds: auth, guards, context switcher, query keys, permissions. Prevents: vazamento multi-estrutura, sessao stale e decisao de permissao somente no client.
- (decision) React consome diretamente os endpoints existentes do backend GestaoEventos, sem BFF e sem nova versao de API durante a convivencia com Angular. Binds: services/api, contratos backend, convivencia Angular. Prevents: prefixo /api/v1 herdado do ManagerPerson, duplicacao de contrato e quebra do Angular por mudanca de backend.
- (decision) Usar uma unica arvore Expo Router: app/(auth) para publico/auth, app/(app) para autenticado; Tabs mobile com jornada, eventos, grupos, painel, perfil; web/tablet largo renderiza as mesmas rotas em shell com sidebar/topbar; rotas administrativas e detalhes profundos ficam fora da barra principal via href null/menu Mais. Binds: routing, shell, mobile/web navigation, deep links. Prevents: rotas duplicadas por plataforma e divergencia de fluxo entre web e mobile.
- (decision) Portar por feature slice reimplementando UI em React Native components: cada slice consulta componente Angular equivalente, service Angular e endpoint backend; nao converter templates Angular automaticamente; modelos/contratos TypeScript novos no React; backend/codigo em execucao vence docs quando houver conflito; forms complexos usam React Hook Form + Zod; tabelas desktop viram listas/cards no mobile quando necessario. Binds: estrategia de implementacao e stories. Prevents: transliteracao mecanica de Angular para React e experiencia mobile quebrada por tabela/template legado.
- (decision) Analytics entra desde o scaffold React com analytics.service plugavel: web envia contrato ge_event para window.dataLayer, nativo inicia com provider no-op/fila local ate decisao de destino mobile, route tracking dispara visualization, fluxos usam entrance/simulation/confirmation, e detalhes nunca carregam labels/valores sensiveis. Binds: scaffold, routing, feature instrumentation, privacidade. Prevents: perda de funil na migracao e vazamento de dados sensiveis em analytics.
